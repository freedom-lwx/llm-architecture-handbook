    00 · 导读：怎么读这套手册¶

    一套面向"真的想搞懂大模型内部"的学习者的源码级架构手册。 不讲故事，不堆名词。每一个公式都能对应到权重张量，每一行结论都能指回源码。

    1. 这套手册解决什么问题¶

    网上的大模型架构文章普遍有三个毛病：

    1. 只讲"是什么"，不讲"怎么算"。说"MLA 用低秩投影压缩 KV"，但不写 \(W^{DKV}\in\mathbb{R}^{d_c\times d}\)、不写缓存的到底是 \(c_t^{KV}\) 还是 \(k_t\)。读者记住了名词，推不动数字。
    2. 只讲"标准件"，不讲"差异点"。所有模型都长一个样（RMSNorm + RoPE + GQA + SwiGLU + MoE），但真正决定能力边界的是那些 5% 的改动——DSA 的 indexer、Kimi 的 latent 维度、DSV4 的压缩注意力——这些恰恰被一笔带过。
    3. 把"架构"和"实现"混为一谈。config 里写了 MTP，但 transformers 建模代码根本不加载它的权重；社区 GGUF 的量化层级变化被当成"新架构"。分不清什么是数学定义、什么是训练产物、什么是推理引擎的工程优化。

    这套手册的目标是把这三层彻底分开：

    • 数学层：每个算子的输入输出张量、公式、为什么收敛/省算力/省显存。
    • 参数层：用真实 config 的数字算一遍 shape 和参数量，不写"假设 hidden=4096"。
    • 代码层：精确到 文件:行号，关键 5–15 行直接贴；训练代码没发布就明说没发布。

    • 想做工程：03 的 KV cache 实现 + 05–07 各章第 7 节"训练 vs 推理"最有用。

    每个模型章节强制 8 节，顺序固定：

    节 内容 不允许出现
    1 一句话定位 营销话术
    2 配置表（从 config.json 抄） "约""大概"
    3 数据流总图（shape 全写死） 省略号
    4 逐块解剖（每个组件四件套） 只给名字不给公式
    5 关键创新深挖（1–3 个独有机制） 复述标准件
    6 参数量与账本（标来源） 把推导当官方数字
    7 训练 vs 推理 假装训练代码公开
    8 检查题（3–5 道） 背诵题

    3. 符号约定（全手册统一）¶

    符号 含义
    \(B\) batch size
    \(S\)（或 \(T\)） 序列长度
    \(d\)（或 \(H\), hidden_size） 模型隐藏维度
    \(L\) Transformer 层数
    \(V\) 词表大小
    \(h\) 注意力头数
    \(d_h\) 每个头的维度（head_dim）
    \(h_{kv}\) KV 头数（GQA/MLA 中小于 \(h\)）
    \(d_c\) MLA 的低秩潜在维度（kv_lora_rank）
    \(d_r\) MLA 查询低秩维度（q_lora_rank）
    \(E\) MoE 专家总数
    \(k\) 每 token 激活的专家数
    \(d_f\)（或 I） FFN 中间维度
    \(x_t\in\mathbb{R}^d\) 第 \(t\) 个 token 的残差流向量
    \(W\) 权重矩阵；下标标明投影方向

    Shape 书写规范：(B, S, d) 表示三维张量。矩阵乘法写成 \(y=xW^\top\)（PyTorch nn.Linear 的约定，权重 shape 是 (out, in)）。

    4. 证据标注规则¶

    每一条事实性陈述必须带且只带一个标签：

    标签 含义 可验证方式
    [源码事实] 直接读源码确认，给出文件:行号 打开对应文件
    [官方材料] config.json / 官方 README / 技术报告 给 URL 或 revision
    [配置值] 从 config.json 读出的超参 数字可核
    [推导] 我用公开数字算出来的，不是官方公布 公式可复算
    [实验结果] 我实际跑了代码得到的 有脚本和输出
    [未知] 查不到/官方未发布 明确说不知道

    不使用"作者报告""社区称""据说"这类模糊来源。如果只有社区说法，标 [未知] 并注明出处不可核验。

    5. 本手册不做什么¶

    • 不做 benchmark 排名。不同 harness、不同量化、不同上下文长度下的吞吐/延迟数字不可直接比较。手册只分析"算法上为什么应该快/慢"。
    • 不教 PyTorch 基础。假设你懂 nn.Linear、@ 矩阵乘、view/transpose、softmax。不懂的话先跑一遍 nanoGPT 的 model.py（330 行，全手册最短）。
    • 不下载大权重。所有分析基于 config + 建模代码，不需要 GPU。
    • 不给"调参指南"。学习率、batch size 这些是工程经验，不是架构问题。
    • 不替官方编故事。配置里没有的、代码里没写的，一律标 [未知]，不做"可能是为了……"的猜测（除非明确写"这是我的推测"）。

        │               │               │               │               │
   nanoGPT         MiniMind        Qwen3.6         GLM-5.2         Kimi-K3 / DSV4
   (教学)           (教学)          (官方)          (官方)           (前沿)
        │               │               │               │               │
