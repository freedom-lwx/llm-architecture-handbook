    05 · GLM-5.2：MLA + DSA/IndexShare + MoE¶

    1. 一句话定位¶

    GLM-5.2 是 DeepSeek-V3 架构的直接演化：78 层全部用 MLA（Multi-head Latent Attention，KV 压到 576 维/token），在此基础上引入 DSA（DeepSeek Sparse Attention，每个 query 只和 top-2048 个最相关 token 做注意力）和 IndexShare（每 4 层共享一次稀疏索引，省掉 3/4 的索引计算），再叠 256 专家 top-8 的 sigmoid 路由 MoE。它的核心命题是：在 MLA 已经把 KV 显存压到极低之后，如何把注意力计算本身从 \(O(T^2)\) 砍到 \(O(T\cdot\text{topk})\)。

    源码：transformers 5.14 内建 models/glm_moe_dsa/modeling_glm_moe_dsa.py（809 行）。config zai-org/GLM-5.2（revision b4734de4）。[源码事实][配置值]

    4. 逐块解剖¶

    4.1 MLA（GlmMoeDsaAttention，:309）¶

    MLA 的数学在 01 章第 10 节已完整推导。这里用 GLM 真实维度走一遍 shape，源码在 :385：

    q_resid = self.q_a_layernorm(self.q_a_proj(hidden_states))      # (B,S,2048)
q_states = self.q_b_proj(q_resid).view(query_shape).transpose(1,2)  # (B,64,S,256)
q_pass, q_rot = split(q_states, [192,64], dim=-1)

compressed_kv = self.kv_a_proj_with_mqa(hidden_states)          # (B,S,576)
k_pass, k_rot = split(compressed_kv, [512,64], dim=-1)
k_pass = self.kv_b_proj(self.kv_a_layernorm(k_pass)).view(key_shape).transpose(1,2)
k_pass, value_states = split(k_pass, [192,256], dim=-1)         # (B,64,S,192)/(B,64,S,256)
k_rot = k_rot.view(B,1,S,64).expand(*k_pass.shape[:-1], -1)     # (B,64,S,64) MQA 共享

q_rot, k_rot = apply_rotary_pos_emb_interleave(q_rot, k_rot, cos, sin)
query = cat([q_pass,q_rot],-1)   # (B,64,S,256)
key   = cat([k_pass,k_rot],-1)    # (B,64,S,256)

    关键点： - KV 缓存的是 576 维（c_KV 512 + k_rot 64），不是 64×256=16384 维。每 token 每层 1152 B（bf16）。78 层 × 1M token ≈ 90 GB——这是单卡 A100 80GB 略超、需要量化或多卡的量级。[推导] - RoPE 用 interleaved（相邻维配对），和 MiniMind/Qwen 的 half-split 不同；DSA indexer 也用 interleaved，保持一致。 - k_rot 是单头（1）expand 到 64 头——位置键在所有头间共享（MQA-style），只有 64 维。 - scaling = 256^{-0.5}；如果配置了 YaRN mscale 会再乘 mscale²（GLM 当前 rope_type=default，无缩放）。

    4.2 DSA Indexer（GlmMoeDsaIndexer，:172）——本章核心¶

    DSA 要解决的问题：MLA 把 KV 显存压下来了，但注意力计算 \(\text{softmax}(QK^\top)V\) 仍是 \(O(T^2)\)——1M 长度下每对 query-key 都算完全不可行。DSA 的思路：先用一个轻量 indexer 给每个 query 选出最相关的 top-2048 个 token，主注意力只在这 2048 个上算 softmax。

    Indexer 有自己独立的轻量投影（不共用 MLA 的 Q/K），源码 :204：

    def forward(self, hidden_states, q_resid, position_embeddings, attention_mask,
            position_ids, past_key_values):
    q = self.wq_b(q_resid)                           # q_resid 是 MLA 的 q_a 输出 (B,S,2048)
    q = q.view(B,S,32,128)                          # indexer 用 32 头×128 维
    q_rot, q_pass = split(q, [64,64], dim=-1)       # 前 64 维 RoPE
    k = self.k_norm(self.wk(hidden_states)).unsqueeze(2)  # (B,S,1,128) 单键头!
    k_rot, k_pass = split(k, [64,64], dim=-1)
    q_rot,k_rot = apply_rotary_pos_emb_interleave(q_rot,k_rot,cos,sin)
    q = cat([q_rot,q_pass],-1); k = cat([k_rot,k_pass],-1).squeeze(2)  # (B,S,128)
    if past_key_values: k = past_key_values.update_indexer(k, layer_idx)  # 独立 indexer K cache

    scores = matmul(q.float(), k.transpose(-1,-2).float().unsqueeze(1)) * (128**-0.5)
    scores = F.relu(scores)                                          # (B,S,32,T)
    weights = self.weights_proj(hidden_states) * (32**-0.5)         # (B,S,32) 每头权重
    index_scores = matmul(weights.unsqueeze(-2), scores).squeeze(-2) # (B,S,T) 加权求和
    # + 因果掩码
    return index_scores.topk(2048, dim=-1).indices.to(int32)         # (B,S,2048)

    逐层拆解这个打分机制：

    1. q 来自 MLA 的 q_resid（2048 维低秩），indexer 用自己的 wq_b: 2048→32×128 投影。注意它复用了 MLA 的 q_a 输出，省一次 h→2048 投影。
    2. k 是单头：wk: 6144→128，所有 query 头共享同一组键。这把 indexer 的 KV cache 压到 128 维/token（比 MLA 主 KV 还小）。
    3. 打分用 ReLU 不是 softmax：\(\text{scores}=\text{ReLU}(q\cdot k/\sqrt{128})\)。ReLU 让不相关的对得 0 分，相关对得正分，再加权——这是"内容相关性"的稀疏选择，不需要归一化。
    4. 多头加权聚合：32 个头各自打出 (B,S,T) 分数，用 weights_proj(h) 生成每头权重，加权求和成 (B,S,T)。不同头可以关注不同模式（一个头找语法依赖、一个头找实体共现）。
    5. 加因果掩码后取 top-2048。

    输出的 topk_indices 怎么用？（:424） - eager/sdpa 路径：构造布尔 mask，把不在 topk 的位置填 -inf，让 softmax 归零。 - flash 路径：直接把 indices 传给 flash_mla_with_kvcache，kernel 只 gather 这 2048 个 KV 做注意力，不实例化完整 \(T\times T\)。

    计算复杂度：注意力从 \(O(T^2 d)\) 降到 \(O(T\cdot 2048\cdot d)\)。1M 长度下，2048 是 \(T\) 的 0.2%——理论加速 ~500 倍（实际受 gather 和 indexer 开销影响，官方报告 FLOPs ↓2.9× with IndexShare）。[官方材料]

    4.3 IndexShare（跨层共享 topk）——GLM 的关键创新¶

    DSA indexer 本身也有成本（每头 q·k 是 \(O(T^2\cdot32)\)，虽然 32 头比主注意力 64 头轻）。GLM 发现：相邻层的稀疏注意力模式高度相关——第 4 层选的 top-2048 个 token，第 5、6 层大部分也会选。

    所以 indexer_types 设计成 full, shared, shared, shared： - full 层（每 4 层一个）：真正跑 indexer，算出 topk_indices。 - shared 层：self.indexer = None，直接用 prev_topk_indices（上一个 full 层传下来的）。

    源码 :406： 

    if self.indexer is not None:          # full 层
    topk_indices = self.indexer(hidden_states, q_resid, ...)
else:                                  # shared 层
    topk_indices = prev_topk_indices   # 直接复用，不计算

    跨层传递在 GlmMoeDsaModel.forward（:715）： 

    topk_indices = None
for i, decoder_layer in enumerate(self.layers):
    hidden_states, topk_indices = decoder_layer(
        ..., prev_topk_indices=topk_indices)  # 每层输出自己的 topk 给下层

    效果：78 层里只有 ~20 个 full indexer（前 3 层 + 每 4 层一个），其余 ~58 层零索引计算。这是"计算复用"思路——和 KV cache 复用 K/V 是同一个哲学，只是复用的是稀疏索引。

    4.4 MoE（GlmMoeDsaMoE，:553）¶

    GLM 的 MoE 是 DeepSeek-V3 风格 sigmoid 路由 + 共享专家：

    class GlmMoeDsaMoE:
    self.experts = GlmMoeDsaExperts(config)       # 256 专家
    self.gate = GlmMoeDsaTopkRouter(config)
    self.shared_experts = GlmMoeDsaMLP(intermediate=moe_intermediate_size*n_shared)
    # n_shared=1, shared expert 中间维 2048（和 routed 专家同尺寸）

    def forward(hidden_states):
        residuals = hidden_states
        _, topk_weights, topk_indices = self.gate(hidden_states)
        hidden_states = self.experts(hidden_states, topk_indices, topk_weights)
        hidden_states = hidden_states + self.shared_experts(residuals)  # 共享专家无条件加

    Router（:472）： 

    router_logits = F.linear(x.float(), gate.weight.float())     # (B*S, 256)
scores = router_logits.sigmoid()                            # 多标签，非 softmax
scores_for_choice = scores + e_score_correction_bias        # noaux bias（当前恒零）
# n_group=1, topk_group=1 时组逻辑退化为全局 top-k
topk_indices = scores_for_choice.topk(8, dim=-1)[1]
topk_weights = scores.gather(1, topk_indices)
topk_weights /= topk_weights.sum(-1,keepdim=True) + 1e-20   # 归一化
topk_weights *= 2.5                                         # routed_scaling_factor

    注意： - sigmoid 不是 softmax：专家分数不互相竞争归一化，一个 token 可以同时给多个专家高分。top-k 后再归一化是另一回事。 - e_score_correction_bias 注册了但当前是全零 buffer（noaux_tc 的偏置在训练时更新，推理 checkpoint 里可能已固化为零或被吸收）。 - routed_scaling_factor=2.5：top-k 归一化后权重和为 1，乘 2.5 补偿"只选 8/256 专家"导致的激活幅度下降（否则输出方差比 dense 小）。 - n_group=1：当前配置没有启用组级路由，直接全局 top-8。代码保留了组逻辑（:490）但 topk_group=1 使其退化。

    专家结构（:514）——权重打包成 3D 张量： 

    self.gate_up_proj = Parameter(empty(256, 2*2048, 6144))   # 256 专家，gate+up 打包
self.down_proj    = Parameter(empty(256, 6144, 2048))
    每专家参数：\(2\times2048\times6144 + 6144\times2048 = 37.7\text{M}\)。256 专家 = 9.66B/层 ×75 MoE 层 ≈ 724B；加 3 dense 层、attention、embedding → 总 ~740B。[推导]

    专家 forward（:526）是参考循环实现：对每个命中的专家，用 index_add_ 把加权结果累加回 token。生产用 grouped GEMM。

    4.5 Dense 层（前 3 层）¶

    前 3 层 mlp_layer_types="dense"，用标准 SwiGLU（GlmMoeDsaMLP，:456），\(d_f=12288\)： 

    down_proj(act_fn(gate_proj(x)) * up_proj(x))
    为什么前几层 dense？底层处理局部语法/词法，需要所有 token 走相同的完整变换；MoE 在高层做语义专业化更有效。这是 DeepSeek-V3 起的标准做法。

    5. 关键创新深挖¶

    5.1 DSA vs MLA vs GQA：三层正交压缩¶

    很多人把 MLA 和 DSA 混为一谈，它们其实解决不同瓶颈：

    机制 压缩对象 手段 省什么
    GQA KV 头数 K/V 头少于 Q 头 KV cache 显存 + 带宽
    MLA KV 维度 K/V 联合低秩投影到 576 KV cache 显存（与头数解耦）
    DSA 注意力参与的 token 数 indexer 选 top-2048 注意力计算 FLOPs

    三者可以叠加：GLM 同时用 MLA（压 KV 维度）+ DSA（压 token 数）。MLA 让 KV cache 从头数解耦（64 头也只存 576 维），DSA 让计算从 \(T^2\) 变成 \(T\cdot\text{topk}\)。IndexShare 再把 indexer 计算省 3/4。

    5.2 DSA 的 indexer 为什么用独立投影而不直接用 MLA 的 Q/K？¶

    可以直接用 MLA 的 \(q,k\) 算相似度选 topk（DeepSeek-V3.2 的 NSA 就是对主 KV 打分）。GLM 用独立 indexer 的原因： 1. 维度不同：主注意力头维 256，indexer 用 128，更轻量。 2. 目标不同：主注意力要算加权 value；indexer 只做"选不选"的二元决策，可以用 ReLU（不需要 softmax 的概率语义）。 3. 独立键缓存：indexer 的 k 只有 128 维单头，缓存极小，可以维护全量历史 K 用于打分（而主注意力靠 topk gather）。 4. 复用 q_resid：虽然投影独立，但 q 侧复用 MLA 的 q_a 低秩输出，不算太浪费。

    5.3 RoPE θ=8M 与 1M 上下文¶

    RoPE 最低频波长约 \(2\pi\theta\)。\(\theta=8\text{M}\) 时最低频波长 ≈ 50M token，远大于 1M 上下文——所以即使不用 YaRN，1M 内所有维度的旋转角都在合理范围（不会超过 \(2\pi\) 太多导致高频维度缠绕）。这和 DSV4 主注意力用 \(\theta=10^4\)（只管 128 窗口）但压缩注意力另用 \(\theta=1.6\times10^5\)+YaRN 形成对比：GLM 用一个大 θ 覆盖全长，DSV4 分层处理。

    6. 参数量与账本¶

    6.1 总参数（推导）¶

    组件 计算 数值
    embed \(154880\times6144\) 0.95B
    lm_head \(6144\times154880\)（解绑） 0.95B
    每层 MLA attention q_a:6144×2048 + q_b:2048×16384 + kv_a:6144×576 + kv_b:512×64×448 + o:16384×6144 + indexer 小项 ≈90M
    每层 dense FFN（3 层） \(3\times6144\times12288\) 226M ×3 = 0.68B
    每层 MoE（75 层） 256×37.7M + shared 37.7M + gate 9.70B ×75 = 727B
    Norm/RoPE 等 小 ~0.1B
    总计 ≈730–740B

    激活参数/层（后 75 MoE 层）：attention 90M + 8 路由专家×37.7M + 1 共享专家 37.7M + gate ≈ 430M；3 dense 层 ≈316M。加权平均约 35B/token。[推导]（官方未公布精确激活参数，35B 为估算）

    6.2 KV cache¶

    每层每 token：MLA 缓存 \(576\times2=1152\text{B}\) + indexer K 缓存 \(128\times2=256\text{B}\)（仅 full indexer 层维护，但 shared 层也读同一个 cache）≈1.4KB。78 层 ×1M ≈ 109 GB（bf16）。DSA 省的是算力不是 KV 显存。[推导]

    6.3 注意力 FLOPs（1M 上下文）¶

    无 DSA：\(2T^2 d_{head}h = 2\times10^{12}\times256\times64 \approx 3.3\times10^{16}\) FLOPs/layer。 DSA top-2048：\(2T\times2048\times256\times64 \approx 6.7\times10^{13}\) FLOPs/layer，降 ~490×。加 IndexShare 后 indexer 成本摊薄，官方报告端到端 FLOPs ↓2.9×。[推导][官方材料]

    7. 训练 vs 推理¶

    • 训练代码未发布。transformers 内建是参考/推理建模，专家用 for-loop + index_add，不是生产 grouped GEMM。
    • MTP：num_nextn_predict_layers=1，权重藏在 model.layers.78（791 个键，含 eh_proj/enorm/hnorm 等），transformers 加载时静默忽略。index_share_for_mtp_iteration=True 表明 MTP 迭代也复用 DSA 索引。实际推测解码由 vLLM/SGLang 实现。[源码事实]
    • DSA 稀疏 mask：eager 路径用 scatter 构造 additive mask；真正生产需 flash_mla_with_kvcache kernel 消费 indices（transformers 的 ALL_ATTENTION_FUNCTIONS 接口已预留 indices 参数）。
    • router bias：e_score_correction_bias 存在但恒零，说明 noaux 均衡在训练末期可能已收敛到接近零，或训练脚本另有处理。[源码事实]
    • 量化：官方权重 283 个 safetensors 分片，bf16；社区有 GGUF/FP8 量化（量化不改架构）。

    8. 检查题¶

    1. MLA 缓存的 576 维具体是哪两部分？为什么必须拆出 64 维单独缓存，而不是把全部 KV 压到 512？

      答案512 维是 $c^{KV}$（位置无关，可低秩吸收），64 维是 $k^{rot}$（要承受 RoPE 旋转）。RoPE 是非线性位置操作，不能被低秩矩阵吸收。如果全压 512 维再对解压后的 K 做 RoPE，就无法利用"把 $W^{UK}$ 吸收进 Q"的推理优化（因为旋转后的 K 不再是 $c^{KV}$ 的固定线性函数）。拆出 64 维单独存、单独旋转、所有头共享，是 MLA 兼顾压缩和位置编码的工程关键。

    2. shared indexer 层直接复用 full 层的 topk_indices，难道不会因为层间表征不同而选错 token 吗？

      答案会有一定误差，但实验表明相邻层的注意力模式高度相关（下层选的相关 token 上层大概率也需要），复用的质量损失可接受，而省掉 3/4 indexer 计算收益巨大。这是工程折中：不是最优选择，而是足够好 + 大幅省算。IndexShare 每 4 层刷新一次，限制了误差累积。

    3. GLM 的 DSA indexer 打分用 ReLU 而不是 softmax，这和主注意力的 softmax 有何功能区别？为什么 indexer 可以用 ReLU？

      答案主注意力 softmax 产生归一化权重用于加权求和 V，权重必须是概率（和为1）。indexer 只做"选哪些 token"的筛选（topk），不需要概率语义；ReLU 让不相关对精确为 0、相关对得正分，天然适合稀疏选择，且省掉 exp 归一化的计算和数值问题。多头加权求和后直接 topk。

    4. GLM 总参 ~740B 但激活 ~35B。如果用 FP8 权重 + 每 token 激活 8/256 专家，单卡至少需要多少显存存权重？为什么 KV cache 反而可能成为瓶颈？

      答案740B ×1B(FP8) ≈ 740GB 权重——单卡放不下，需要多卡张量/专家并行。KV cache 1M 约 109GB(bf16)，即使权重分多卡，KV cache 也需大量显存；DSA 省算力不省 KV，这是长上下文推理的主要显存压力，需要 paged KV + KV 量化。

    5. routed_scaling_factor=2.5 的作用是什么？如果设成 1 会怎样？

      答案top-k 归一化后 8 个专家权重和为 1，但每个专家输出的尺度是为"独立贡献"设计的；只取 8/256 并加权平均后，激活幅度比 dense（全量）小。乘 2.5 补偿这个尺度下降，保持 MoE 输出和 dense 输出方差一致。设成 1 会导致残差流里 MoE 分支贡献偏弱、模型需在训练中自行补偿，可能影响收敛。
