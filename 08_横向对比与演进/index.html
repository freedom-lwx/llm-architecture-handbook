    08 · 横向对比与演进¶

    1. 一句话定位（六个模型放一起）¶

    模型 年代层 一句话 总参/激活
    nanoGPT 2018 GPT-2 复刻 无任何压缩的教学基线，一切瓶颈的原点 124M / 124M
    MiniMind 2023 Llama 最小化 现代五件套（RoPE/RMSNorm/GQA/SwiGLU/KV cache）的最小可读实现 ~26–81M / 同
    Qwen3.6-27B 2026 Dense-Hybrid：线性状态机扛长程，稀疏全注意力做检索 27B / 27B
    GLM-5.2 2026 每层 MLA + DSA 稀疏化 token + IndexShare 复用索引 ~740B[推导] / ~35B[推导]
    Kimi-K3 2026 KDA 状态机 + Gated MLA + Latent MoE + 块残差，NoPE 2.8T[官方] / 104B[官方]
    DSV4-Flash 2026 mHC 4 流 + 分层压缩注意力 + FP4 专家 + DSpark ~282B[推导] / ~14B[推导]

    2. 四大替换件矩阵¶

    六个模型的差异可以完全收敛到四个维度。其余（Embedding、RMSNorm、残差、SwiGLU 骨架）95% 相同。

    2.1 位置编码¶

    模型 方式 θ / 特殊 外推
    nanoGPT 可学习查表 wpe 无 θ，表长 1024 不能
    MiniMind RoPE half-split θ=1e6 YaRN ×16 可选
    Qwen3.6 mrope 3D + partial(0.25) θ=1e7 262K 原生
    GLM-5.2 RoPE interleave θ=8e6 1M 原生
    Kimi-K3 NoPE（MLA 层 rotary_emb=None） — 由 KDA 状态携带
    DSV4 双 RoPE 滑窗 θ=1e4；压缩 θ=1.6e5+YaRN×16 1M

    演进逻辑：查表（不可外推）→ RoPE（可外推，相对位置）→ mrope（多模态 3D）→ NoPE（线性状态机自带时序）/ 双 RoPE（分层注意力用不同频率尺度）。

    2.2 注意力（最核心的差异化维度）¶

    模型 注意力类型 头数/维度 KV 缓存/token 长上下文策略
    nanoGPT MHA 12×64 3KB（无 cache 实现） 无，T≤1024
    MiniMind GQA 8Q/4KV×96 1.5KB KV cache + RoPE 外推
    Qwen3.6 48 GatedDeltaNet + 16 GQA 线性:48×128；全:24Q/4KV×256 线性层定长 1.5MB；全注意力 4KB 线性状态 O(T) + 每 4 层精确检索
    GLM-5.2 MLA + DSA 64 头，q2048/kv512+64 1.4KB（含 indexer） MLA 压维 + 每 query top-2048 token + IndexShare
    Kimi-K3 69 KDA + 24 Gated MLA KDA 96×128；MLA 96 头 q1536/kv512+64 KDA 定长 ~3MB；MLA 1.15KB 状态机 + 每 4 层 MLA 精确检索；NoPE
    DSV4 单头 MLA + 滑窗 + 压缩 64Q/1KV×512，分 8 组低秩 O 1KB + 压缩条目 128 窗 + ratio 4/128 软池化 + top512

    三条技术路线： 1. GQA 路线（MiniMind/Qwen 全注意力层）：减少 KV 头数。 2. MLA 路线（GLM/Kimi/DSV4）：把 K/V 压成低秩向量，缓存与头数解耦。 3. 线性/递归路线（Qwen GatedDeltaNet / Kimi KDA）：用定长状态矩阵替代 KV cache，O(T) 且不增长，代价是有损压缩。

    三条路线都和"稀疏化计算"正交： - GLM/DSV4 在 MLA 之上再稀疏化参与注意力的 token（top-2048 / top-512 压缩条目）。 - Qwen/Kimi 用"线性层 + 稀疏全注意力层"混合。

    2.3 FFN / MoE¶

    模型 FFN 结构 专家数/topk 专家维度 路由 共享专家
    nanoGPT GELU 4C，2 矩阵 dense 3072 — —
    MiniMind SwiGLU，3 矩阵 可选 4 / top1 2432 softmax + aux loss 0
    Qwen3.6 SwiGLU Dense dense 17408 — —
    GLM-5.2 SwiGLU + MoE 256 / top8 latent 2048 sigmoid + noaux bias 1
    Kimi-K3 SITU + Latent MoE 896 / top16 latent 3584→3072 sigmoid + e_score_bias 2
    DSV4 SwiGLU(clamp) + FP4 MoE 256 / top6 2048 sqrtsoftplus + noaux bias；前 3 层 hash 1

    演进逻辑： - GELU(2 矩阵) → SwiGLU(3 矩阵门控) → SITU(有界激活，低精度友好)。 - Dense → MoE（总参与激活解耦）→ Latent MoE（专家在半维空间算，控总参）→ FP4 MoE（权重量化控显存）。 - 路由：softmax + aux loss → sigmoid + noaux bias → hash 路由（底层静态选择）。

    2.4 残差形态¶

    模型 残差 说明
    nanoGPT 单流 Pre-Norm \(x+\text{sub}(\text{Norm}(x))\)
    MiniMind 单流 Pre-Norm RMSNorm 同上，换 Norm
    Qwen3.6 单流 Pre-Norm 标准
    GLM-5.2 单流 Pre-Norm 标准
    Kimi-K3 AttnRes（12 层一块的可学习聚合） 块内跨层线性注意力残差
    DSV4 mHC（4 条并行流 + Sinkhorn 双随机混合） 每子层折叠/展开 4 流

    残差是最晚被改动的组件：前四个模型都用经典 Pre-Norm；Kimi 和 DSV4 在万亿规模发现单流残差的深层退化问题，分别用块聚合和多流超连接增强。

    3. 参数量与账本总账¶

    3.1 总参与激活参¶

    模型 总参 激活参/层 KV cache/token 1M 上下文 KV（bf16）
    nanoGPT 124M 124M 3KB（无 cache） —
    MiniMind ~26–81M 同 12KB 12GB
    Qwen3.6 27B 27B 64KB（仅16全注意力层）+ 线性层定长 72MB ~64GB
    GLM-5.2 ~740B[推导] ~35B[推导] ~1.4KB ~109GB
    Kimi-K3 2.8T[官方] 104B[官方] KDA 定长 + 24 层 MLA 1.15KB ~27GB
    DSV4 ~282B[推导] ~14B[推导] 1KB + 压缩条目 ~6–10GB

    [推导] 处用 config 数字按以下公式自洽计算： - 注意力参数：Q/K/V/O 投影之和（MLA 用低秩维度）。 - FFN/MoE：dense 层 \(3d\cdot d_f\)；MoE 层 \(E\cdot 3d_{\text{expert}}\cdot d_{f,\text{expert}}\) + 共享专家。 - 关键陷阱：Kimi 专家在 latent 3584 维，必须用 3584 而非 7168，否则得到 5.4T（错误）而非 2.8T（官方）。

    3.2 三大显存桶¶

    推理显存 = 权重 + KV cache + 激活。

    权重解决手段 KV 解决手段
    MiniMind/Qwen(dense) 量化（GGUF 等） GQA + paged KV
    GLM MoE（总参大但每卡只放部分专家） MLA 压维
    Kimi Latent MoE + 8bit 压缩 KDA 定长状态 + MLA
    DSV4 FP4 专家 + FP8 非专家 单头 MLA + 压缩注意力

    DSV4 是唯一一个三个桶都极致压缩的：FP4 权重、压缩 KV、稀疏注意力计算。这解释了它为什么叫 "Flash"——目标是单节点低延迟。

    4. 计算复杂度对比（每 token 注意力）¶

    模型 注意力 FLOPs 随 T 增长
    MHA（nanoGPT） \(O(T\cdot d)\) per layer，但有 \(T^2\) 注意力矩阵 \(O(T^2)\)
    GQA（MiniMind） 同上，KV 头减少 \(O(T^2)\)
    GatedDeltaNet/KDA（Qwen 线性层/Kimi KDA） \(O(d_k d_v)\) 状态更新，与 T 无关 \(O(1)\) per token（定长状态）
    MLA 全注意力（GLM 无 DSA） \(O(T\cdot d)\)（MLA 不省计算只省显存） \(O(T^2)\)
    MLA + DSA（GLM） \(O(\text{topk}\cdot d)\)，topk=2048 \(O(T\cdot\text{topk})\)
    MLA + 压缩（DSV4） \(O((128+512)\cdot d)\) \(O(T\cdot 640)\)

    关键认知： - MLA 省 KV 显存但不省注意力计算——这是常见误解。GLM 必须叠加 DSA 才把计算也降下来。 - 线性注意力省计算也省 KV（状态定长），但有损精度，需要全注意力层补偿。 - DSV4 的压缩注意力把"参与计算的 KV 条数"降到 ~640（128 窗 + 512 压缩），是六个模型里每 token 注意力 FLOPs 最低的。

    5. 训练 vs 推理：开源边界¶

    模型 训练代码 推理参考代码 MTP/推测解码 量化
    nanoGPT ✅ 完整 train.py ✅ 自带 无 无
    MiniMind ✅ 完整（pretrain/SFT/LoRA/DPO/PPO/GRPO） ✅ 自带 无 无
    Qwen3.6 ❌ 未发布 transformers 内建 权重在，引擎实现 社区 GGUF
    GLM-5.2 ❌ 未发布 transformers 内建 权重在 layers.78，引擎实现 bf16，社区量化
    Kimi-K3 ❌（MoE 训练直接 raise） HF custom code（fla-core） cfg=0/报告称1，不一致 8bit compressed
    DSV4 ❌ 未发布 官方 inference/（tilelang） 代码完整但 generate.py 未接线 FP8+FP4 原生

    重要事实（反复强调）： 1. 所有前沿模型的训练代码都没发布。开源的只是推理参考实现。 2. MTP 在四个官方模型里都是"权重存在、参考 forward 不跑"，实际推测解码靠 vLLM/SGLang。 3. 量化（GGUF/FP8/FP4）不改变架构，只改变数值精度。DavidAU 的 IQ2_XXS/Q4_K_M 等是量化层级，不是新模型。 4. transformers 内建建模是"参考实现"，专家用 for-loop；生产用 grouped GEMM / fused kernel，数学等价但性能差几个数量级。

    6. 演进脉络（2018–2026）¶

    2018 GPT-2 (nanoGPT 复刻)
 │  可学习位置表, LayerNorm+bias, MHA, GELU, 无cache
 │  瓶颈: T² 注意力, KV 显存, 长上下文不可外推
 ▼
2023 Llama 系 (MiniMind 最小化)
 │  RoPE(可外推), RMSNorm(去bias), GQA(KV头减半),
 │  SwiGLU(门控FFN), KV cache(增量解码)
 │  解决: 外推 + KV 显存; 仍 T²
 ▼
2024  MoE 成熟 (DeepSeek-V3 风格)
 │  sigmoid 路由 + noaux bias + 共享专家
 │  总参与激活解耦 → 万亿模型可行
 │  瓶颈: KV cache 随头数涨, T² 仍在
 ▼
2025  MLA 普及 (DeepSeek-V2 起)
 │  K/V 联合低秩压缩, KV 与头数解耦
 │  解决: KV 显存; 但 T² 计算仍在
 ▼
2025–2026 三条分叉
 │
 ├─ 稀疏注意力路线 (GLM-5.2)
 │   MLA + DSA top-k token + IndexShare 跨层复用索引
 │   每层都是注意力, 但只算 top-2048
 │
 ├─ 线性/递归路线 (Qwen3.6, Kimi-K3)
 │   GatedDeltaNet/KDA 定长状态机, O(T) 无 KV 增长
 │   + 稀疏全注意力层做精确检索
 │   Kimi 进一步: NoPE, Latent MoE, AttnRes
 │
 └─ 压缩注意力路线 (DSV4)
     MLA 单头 + 滑窗 + KV 软池化压缩 + indexer
     mHC 多流残差 + FP4 MoE + DSpark 推测解码
     三层显存/计算全压缩 → "Flash"

    每一步都在解决上一代的某个瓶颈，同时引入新成本： - GQA 省 KV 但降低精度 → MLA 用低秩恢复表达力。 - MLA 省显存但不省计算 → DSA/压缩稀疏化计算。 - MoE 扩参数但增通信/显存 → Latent MoE 降专家维度，FP4 降权重显存。 - 深层单流残差退化 → AttnRes/mHC 增强跨层连接。 - 自回归慢 → MTP/DSpark 推测解码（但开源实现普遍未接线）。

    7. 如何继续深入¶

    这套手册覆盖了"架构级"理解。往下走有三个方向：

    1. 算子/内核级：读 DSV4 的 kernel.py（tilelang FP4 GEMM）、fla-core 的 chunk/fused recurrent delta rule、FlashAttention/flash-mla。理解数学怎么变成 GPU kernel。
    2. 训练级：MiniMind 是唯一开放训练代码的，从 train_pretrain.py 跑到能复现 loss 曲线；再读 DeepSeek-V3 技术报告理解 MoE 训练工程（aux-loss-free、FP8 训练、并行策略）。
    3. 推理引擎级：vLLM/SGLang 怎么实现 paged KV、MLA、DSpark/NEXTN 推测解码、FP4/FP8——对照本手册的"权重在但参考实现不跑"部分，看引擎怎么把它们接起来。

    最小可动手实验（在 ~/.cache/modelstudy/）： - 跑 nanoGPT 训练，改 wpe→RoPE、MHA→GQA，观察 loss/显存。 - 在 MiniMind 上把 GQA 改成 MLA（低秩 KV），实测 KV cache 变化。 - 用 numpy 复现 DSV4 Compressor 的软池化（~40 行），验证压缩条目 shape。 - 对比 GLM Indexer 和 DSV4 Indexer 的打分差异（ReLU vs einsum+FP4）。
