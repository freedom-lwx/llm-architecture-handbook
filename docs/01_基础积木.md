## 1. Token Embedding 与 LM Head

### 定义

把整数 token id 映射成向量，最后再把向量映射回词表上的概率分布。

### 数学

- Embedding：查表 $E\in\mathbb{R}^{V\times d}$，$x_t = E[\text{id}_t]\in\mathbb{R}^d$。
- LM Head：线性投影 $\text{logits}_t = x_t W_h^\top\in\mathbb{R}^V$，$W_h\in\mathbb{R}^{V\times d}$。
- **权重捆绑（weight tying）**：令 $W_h = E$。nanoGPT 和 MiniMind 默认开；GLM/Kimi/DSV4/Qwen3.6 关。

### Shape（以 GLM-5.2 为例，$V=154880, d=6144$）

```
input_ids:      (B, S)            int64
embed_tokens:   (B, S, 6144)      bf16
... 经过 L 层 ...
lm_head:        (B, S, 154880)    bf16
```

词表嵌入参数量：$V\cdot d = 154880\times 6144 \approx 951\text{M}$。这是单块最大的权重，约占 GLM 总参数的 0.13%；但在小模型（MiniMind 26M）里占比极大。`[推导]`

### 源码锚点

- nanoGPT `model.py:138`：`self.transformer.wte.weight = self.lm_head.weight` —— 一行完成捆绑。`[源码事实]`
- MiniMind `model_minimind.py:242`（`MiniMindForCausalLM.__init__`）：`if self.config.tie_word_embeddings: self.model.embed_tokens.weight = self.lm_head.weight`，并在类属性 `_tied_weights_keys` 声明。`[源码事实]`
- GLM `configuration_glm_moe_dsa.py`：`tie_word_embeddings=False`。

### 为什么捆绑

- 减少 $Vd$ 个参数（对 50257×768 = 38M，在 nanoGPT 里占 30%）。
- 正则化效果：输入空间和输出空间共享几何结构。
- 大模型解绑：词表嵌入只占总参数 0.1%，捆绑带来的收益可忽略；解绑允许输出头用不同的学习率/初始化。

### 去掉会怎样

- 解绑不影响数学表达能力，只是多一块参数。
- 小模型解绑会明显过拟合 + 显存翻倍。

## 2. RMSNorm（Root Mean Square Layer Normalization）

### 定义

只用均方根做缩放，不要 LayerNorm 的均值中心化和偏置。现代大模型（Llama 起）全部用它。

### 数学

给定 $x\in\mathbb{R}^d$：

$$\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum_{i=1}^{d}x_i^2 + \epsilon}}\odot \gamma$$

其中 $\gamma\in\mathbb{R}^d$ 是可学习缩放（初始化为全 1），$\epsilon=10^{-6}$ 防除零。

对比 LayerNorm：$\frac{x-\mu}{\sigma}\gamma+\beta$，多了均值减法和偏置。RMSNorm 省了一个 reduce-mean 和一个偏置，等价于假设"均值为零已经被残差路径保证"。

### Shape

逐 token 逐向量归一化，shape 不变；参数只有 $\gamma$：$d$ 个标量。无运行时统计量（和 BatchNorm 不同）。

### 源码锚点 `[源码事实]`

MiniMind `model_minimind.py:50`：

```python
class RMSNorm(torch.nn.Module):
    def __init__(self, dim, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))
    def norm(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
    def forward(self, x):
        return (self.weight * self.norm(x.float())).type_as(x)
```

注意 `.float()`：归一化在 fp32 下做，再 cast 回 bf16/fp16。这是所有大模型的标准做法——fp16 的 $\frac{1}{\sqrt{\cdot}}$ 在小数值上精度不够。

### 为什么是它而不是 LayerNorm

- 省算力：少一次均值减法（在大 $d$ 上不可忽略）。
- 实证表现相同或更好（Zhang & Sennrich 2019）。
- 不要偏置：现代大模型发现 bias 项无用甚至有害，绝大多数 `nn.Linear(bias=False)`。

### 去掉会怎样

- 没有归一化，深层 Transformer 训练必崩（激活值指数增长/消失）。
- 换回 LayerNorm 能跑，但慢一点点，效果无显著差别。

## 3. 残差连接与 Pre-Norm

### 定义

每个子层（注意力、FFN）外面包一条恒等捷径：

$$x_{\ell+1} = x_\ell + \text{SubLayer}(\text{Norm}(x_\ell))$$

这叫 **Pre-Norm**（归一化在子层之前）。GPT-2 用的是 Post-Norm（归一化在子层之后：$x_{\ell+1}=\text{Norm}(x_\ell+\text{SubLayer}(x_\ell))$）。nanoGPT 是 Pre-Norm。

### 为什么 Pre-Norm 赢了

Post-Norm 在深层时梯度要穿过一连串 Norm，容易梯度爆炸/消失，需要精心调 warmup。Pre-Norm 的残差路径是"干净"的恒等映射，梯度可以直接流回任意浅层，训练稳定得多。

> **反直觉点**：Pre-Norm 的最终输出在最后还会过一次 `FinalNorm`（否则最后一个残差分支没被归一化）。nanoGPT `model.py:131`（`GPT.__init__` 里 `self.transformer = nn.ModuleDict(... ln_f = LayerNorm(...))`）的 `ln_f` 就是这个。`[源码事实]`

### 源码锚点

nanoGPT `model.py:104`（`Block.forward`）：

```python
def forward(self, x):
    x = x + self.attn(self.ln_1(x))   # Pre-Norm + 残差
    x = x + self.mlp(self.ln_2(x))
    return x
```

GLM/Kimi/DSV4/Qwen/MiniMind 全部同构，只是把 `LayerNorm` 换成 `RMSNorm`。

### 高级变体（后面模型章节细讲）

- **AttnRes（Kimi）**：把残差从"单层直连"升级成"跨 12 层块的可学习聚合"。
- **mHC（DSV4）**：同时维护 4 条并行残差流，用 Sinkhorn 双随机矩阵混合。

这两个不是新范式，而是在 Pre-Norm 骨架上的工程增强。

## 4. RoPE（Rotary Position Embedding）

### 定义

绝对位置编码，但作用在 Q/K 上时表现为相对位置。对 $d_h$ 维向量的每一对相邻维度做二维旋转，旋转角度由位置 $t$ 和维度索引 $i$ 决定。nanoGPT 用可学习查表 `wpe`；从 MiniMind 开始全部用 RoPE。

### 数学

把头维度 $d_h$ 两两配对成 $d_h/2$ 个二维平面。第 $i$ 对（$i=0,1,\dots,d_h/2-1$）的旋转角频率：

$$\theta_i = \frac{1}{b^{2i/d_h}}, \quad b=\text{rope\_theta}$$

位置 $t$ 处的角度 $\phi_{t,i}=t\cdot\theta_i$。旋转：

$$\begin{pmatrix}q'_{2i}\\q'_{2i+1}\end{pmatrix}
=
\begin{pmatrix}\cos\phi_{t,i} & -\sin\phi_{t,i}\\ \sin\phi_{t,i} & \cos\phi_{t,i}\end{pmatrix}
\begin{pmatrix}q_{2i}\\q_{2i+1}\end{pmatrix}$$

**关键性质**：旋转后做点积 $\langle q'_t, k'_s\rangle$ 只依赖 $t-s$（相对位置），不依赖绝对位置。证明：旋转矩阵构成群，$R(\phi_t)^\top R(\phi_s)=R(\phi_s-\phi_t)$。

### 两种实现：half-split vs interleave

两种把"二维对"映射到张量索引的方式：

- **half-split（Llama 风格）**：前 $d_h/2$ 维和后 $d_h/2$ 维配对。`rotate_half(x) = [-x[d/2:], x[:d/2]]`，然后 $x\cos + \text{rotate\_half}(x)\sin$。MiniMind、Qwen 用这个。
- **interleaved（GPT-NeoX / GLM 风格）**：相邻两维配对 $(0,1),(2,3),\dots$。GLM 的 indexer 明确用这个（`apply_rotary_pos_emb_interleave`）。

两者数学等价，只是索引顺序不同；**不能混用**，否则位置信息错乱。

### Shape（GLM $d_h=256$, 旋转 64 维）

```
q, k:        (B, h=32, S, 256)
cos, sin:    (1, S, 64)           ← 只对最后 64 维（rope_head_dim）做旋转
apply_rotary: q/k shape 不变
```

### 频率与外推

- $\theta_i$ 随 $i$ 增大指数衰减：低维（小 $i$）高频（短程），高维低频（长程）。
- $b$（rope_theta）越大，最低频波长越长，模型"看得见"的位置越远：
  - MiniMind $b=10^6$，最低频波长 $\approx 2\pi b \approx 6.3\text{M}$ token。
  - GLM $b=8\times10^6$。
  - Qwen3.6 $b=10^7$。
  - DSV4 主注意力 $b=10^4$（只管 128 窗口），但**压缩注意力用 $b=1.6\times 10^5$ + YaRN×16**——因为压缩条目代表的位置跨度是原始 token 的 4 或 128 倍。

### YaRN（Yet another RoPE ExtensioN）

外推到训练长度之外时，高频维度可以线性外推、低频维度需要"压一下"。YaRN 引入维度相关的混合系数：

$$\theta'_i = \theta_i\left((1-\gamma_i) + \frac{\gamma_i}{s}\right)$$

其中 $s$ 是长度缩放因子，$\gamma_i\in[0,1]$ 是维度 $i$ 的 ramp 函数（高频 $\gamma=0$ 不变，低频 $\gamma=1$ 缩放）。DSV4 的 `rope_scaling.factor=16, original_max_position_embeddings=65536` 就是把 64K 扩到 1M。

### 源码锚点 `[源码事实]`

MiniMind `model_minimind.py:62` `precompute_freqs_cis`：

```python
freqs = 1.0 / (rope_base ** (torch.arange(0, dim, 2)[:dim//2].float() / dim))
t = torch.arange(end)
freqs = torch.outer(t, freqs).float()           # (end, dim/2)
freqs_cos = torch.cat([torch.cos(freqs), torch.cos(freqs)], dim=-1)  # half-split
freqs_sin = torch.cat([torch.sin(freqs), torch.sin(freqs)], dim=-1)
```

注意它把 cos/sin 复制成两半，配合 `rotate_half` 的 half-split 索引。

### 去掉会怎样

- 模型完全丧失顺序感知（注意力对 token 排列不变），除了因果掩码外没有任何位置信息，等同于词袋。
- Kimi-K3 是个**例外**：MLA 层的 `rotary_emb=None`（NoPE），位置靠 KDA 状态机的递推隐式携带。06 章细讲。

## 5. 多头注意力 MHA

### 定义

把 $d$ 维向量切成 $h$ 个 $d_h=d/h$ 维的头，每个头独立做缩放点积注意力，最后拼接投影回去。

### 数学

$$Q = xW_Q^\top,\quad K = xW_K^\top,\quad V = xW_V^\top,\quad W_{Q,K,V}\in\mathbb{R}^{h d_h\times d}$$

每个头：

$$\text{Attn}_h(Q_h,K_h,V_h) = \text{softmax}\left(\frac{Q_h K_h^\top}{\sqrt{d_h}} + M\right)V_h$$

$M$ 是因果掩码：$M_{ij}=-\infty$ if $j>i$。输出：

$$\text{out} = [\text{Attn}_1;\dots;\text{Attn}_h] W_O^\top,\quad W_O\in\mathbb{R}^{d\times h d_h}$$

### Shape（nanoGPT $h=12, d_h=64, S=1024$）

```
x:           (B, S=1024, d=768)
c_attn(x):   (B, S, 2304)          ← 一次投影出 Q,K,V
split:       3 × (B, S, 768)
view/trans:  3 × (B, 12, S, 64)
scores:      (B, 12, S, S)         ← O(S²) 的来源！128×128=16K 个标量/头
softmax
@V:          (B, 12, S, 64)
concat:      (B, S, 768)
c_proj:      (B, S, 768)
```

### 计算量

每层注意力：$2BSd(3d) + 2BS^2 d_h h + 2BSd\cdot d = 6B S d^2 + 2B S^2 d$。
- 第一项是投影，和 $S$ 线性。
- 第二项是 $S^2$ 项——长上下文的瓶颈。
- 当 $S \gg d$（如 $S=1\text{M}, d=6144$），第二项是 $2\times 10^6\times 6144\approx 1.2\times 10^{10}$/token/层，完全不可承受。

这就是后面所有"稀疏/压缩/线性注意力"要解决的问题。

### 源码锚点 `[源码事实]`

nanoGPT `model.py:29-76`（`CausalSelfAttention`）是教科书实现，逐行对应上面的公式。

### Flash Attention

`F.scaled_dot_product_attention(..., is_causal=True)` 不实例化 $S\times S$ 的注意力矩阵，而是分块（tile）在 SRAM 里 online softmax，把 HBM 访问从 $O(S^2)$ 降到 $O(S)$。nanoGPT 自动用它，但**flash 不改变数学结果，只改变速度和显存**。

## 6. 分组查询注意力 GQA

### 定义

MHA 里 Q 有 $h$ 个头，K/V 也有 $h$ 个头。GQA 让 K/V 只有 $h_{kv}<h$ 个头，每个 KV 头被 $h/h_{kv}$ 个 Q 头共享。极端情况 $h_{kv}=1$ 叫 MQA（Multi-Query Attention）；$h_{kv}=h$ 就是 MHA。

### 数学

K/V 投影到 $h_{kv}d_h$ 维，然后沿头维度复制 $g=h/h_{kv}$ 次：

$$K' = \text{repeat\_interleave}(K, g),\quad V' = \text{repeat\_interleave}(V, g)$$

之后照常 MHA。

### Shape（MiniMind $h=8, h_{kv}=4, d_h=96$）

```
q_proj:  (B,S, 8×96=768)
k_proj:  (B,S, 4×96=384)      ← 比 MHA 少一半 K/V 写入
v_proj:  (B,S, 4×96=384)
repeat_kv(k, n_rep=2): (B, 4, S, 96) → (B, 8, S, 96)
```

### 为什么

推理时 KV cache 是自回归生成的显存瓶颈（见下一节）。GQA 把 KV cache 减小 $g$ 倍：

- 精度损失极小（K/V 头之间高度冗余）。
- Llama-2/3、MiniMind、Qwen3.6 全注意力层都用 GQA。
- MLA（第 10 节）是更激进的压缩：把 K/V 压到一个低秩向量，而不是减少头数。

### 源码锚点 `[源码事实]`

MiniMind `model_minimind.py:86` `repeat_kv`：

```python
def repeat_kv(x, n_rep):
    bs, slen, n_kv, hd = x.shape
    if n_rep == 1: return x
    return (x[:, :, :, None, :]
            .expand(bs, slen, n_kv, n_rep, hd)
            .reshape(bs, slen, n_kv * n_rep, hd))
```

### 去掉会怎样

换回 MHA：训练精度差异在误差范围内（多篇消融显示 GQA ≥ 8 KV 头几乎无损），但推理 KV cache 线性膨胀，长上下文必爆显存。`[推导]`

## 7. KV Cache

### 定义

自回归生成第 $t$ 个 token 时，前面 $1..t-1$ 的 K/V 不变。把它们缓存下来，每步只算新 token 的 Q（1 个）和 K/V（1 个），避免 $O(t^2)$ 重算。

### 数学与 shape（以 MiniMind 单层为例）

**无 cache，每步重算全部**：
```
step t:  输入 (B, t, d)，Q/K/V 都算 t 个，attention (B, h, t, t)
总计算:  Σ_{t=1}^T O(t²d) = O(T³d)
```

**有 cache**：
```
prefill: 输入 (B, S, d)，填充 cache，shape (B, h_kv, S, d_h)
decode step t:
  新 token:  x_t (B, 1, d)
  新 q:      (B, h, 1, d_h)
  新 k/v:    (B, h_kv, 1, d_h)
  cat 到 cache: (B, h_kv, t, d_h)   ← 只追加，不重算
  attention: (B, h, 1, t) @ (B, h, t, d_h)  → O(td)
总计算:  prefill O(S²d) + Σ_{t=1}^T O(td) = O(S²d + T²d)  （比无 cache 的 O(T³) 好一个 T）
```

### 每 token 缓存字节数

MiniMind 单层：$2 \cdot h_{kv}\cdot d_h \cdot \text{bytes}$。bf16 = 2 字节：
$$2 \times 4 \times 96 \times 2 = 1536\text{ B/token/层}$$
8 层：$12.3\text{ KB/token}$。1M 上下文 $\approx 12\text{ GB}$。

对比：

| 模型 | 每层缓存/token | L 层 | 1M 上下文 |
|---|---|---|---|
| MiniMind GQA | 1.5 KB | 8 | 12 MB |
| Qwen3.6 全注意力 GQA | $2\times4\times256\times2=4$ KB | 16 | 64 MB（全注意力层 only，线性层是定长状态） |
| GLM MLA | $2\times 576\times2=2.3$ KB | 78 | 180 MB |
| Kimi Gated MLA | $2\times 576\times2=2.3$ KB | 24 | 54 MB（MLA 层）；KDA 层定长状态 |
| DSV4 MLA 单 KV 头 | $2\times 512\times2=2$ KB | 43 | 86 MB（还有压缩条目） |

以上数字均用各模型 config 中 `hidden_size/num_key_value_heads/head_dim/kv_lora_rank/qk_rope_head_dim` 代入计算。`[配置值][推导]`

MLA 把 K/V 压成 $d_c+64$ 的低秩向量（下一节），所以缓存量是 $O(d_c)$ 而不是 $O(h_{kv}d_h)$。

### 源码锚点

MiniMind `model_minimind.py:121`（`Attention.forward`）：

```python
if past_key_value is not None:
    xk = torch.cat([past_key_value[0], xk], dim=1)   # 追加旧 K
    xv = torch.cat([past_key_value[1], xv], dim=1)
past_kv = (xk, xv) if use_cache else None
```

nanoGPT **故意没有 KV cache**（教学简洁），`generate` 每步把整段重新前向。我们在之前的实验里实测过：无 cache 的输出和有 cache 在数学上完全相等（`torch.equal=True`），只是慢。`[实验结果]`

### paged KV cache（vLLM 等）

上面的 `torch.cat` 每步重新分配内存，碎片严重。生产系统用操作系统虚拟页的思路：把 cache 切成固定大小的 block（如 16 token），用一张 block table 间接寻址。这是引擎层优化，不改模型数学。

### 去掉会怎样

功能上完全等价，只是速度从"能用"变成"不可用"（生成 1000 token 慢 ~500 倍）。

## 8. SwiGLU 前馈网络

### 定义

Transformer 块里第二个子层。原始 GPT 用 GELU(4C)；现代模型全用 SwiGLU（Llama 起），有三个矩阵而非两个。

### 数学

$$\text{FFN}(x) = \left(\text{SiLU}(xW_g^\top) \odot xW_u^\top\right) W_d^\top$$

- $W_g, W_u \in \mathbb{R}^{d_f\times d}$（gate 和 up）
- $W_d \in \mathbb{R}^{d\times d_f}$（down）
- $\text{SiLU}(z)=z\sigma(z) = z/(1+e^{-z})$
- $\odot$ 是逐元素乘

$d_f$ 的选择：标准是 $\frac{8}{3}d\approx 2.67d$（Llama 系），再对齐到 256 的倍数。
- MiniMind：$\lceil \pi d/64\rceil\times 64 \approx 3.14d$（作者的小趣味）。`[配置值]`
- GLM MoE 专家 $d_f=2048$（latent 维度 2048 下，$d_f\approx d$）。`[配置值]`

### Shape（GLM dense 层 $d=6144, d_f=12288$）

```
x:           (B, S, 6144)
gate_proj:   (B, S, 12288)
up_proj:     (B, S, 12288)
SiLU(gate)*up: (B, S, 12288)
down_proj:   (B, S, 6144)
参数: 3 × 6144 × 12288 ≈ 226M/层
```

### 源码锚点 `[源码事实]`

GLM `modeling_glm_moe_dsa.py:456`（`GlmMoeDsaMLP`）：

```python
class GlmMoeDsaMLP:
    def forward(self, x):
        return self.down_proj(self.act_fn(self.gate_proj(x)) * self.up_proj(x))
```

MiniMind `model_minimind.py:136`（`FeedForward`）同构。

### 为什么是 SwiGLU 而不是 GELU

- GLU 变体有门控机制，实证上梯度流更好、收敛更快。
- 代价：多一个 $d\times d_f$ 矩阵。为了保持参数量和 GELU(4C) 相当，$d_f$ 取 $\frac{2}{3}\times 4d = \frac{8}{3}d$。

### 去掉会怎样

换回 GELU(4C)：能跑，损失点困惑度，省 1/3 的 FFN 参数。

## 9. MoE（Mixture of Experts）与路由

### 定义

把 FFN 复制 $E$ 份（专家），每个 token 只激活其中 $k$ 个。路由网络（gate）决定每个 token 去哪些专家。总参数随 $E$ 增长，但计算量只随 $k$ 增长——这是把"模型大小"和"推理成本"解耦的唯一成熟方法。

### 数学

$$\text{MoE}(x) = \sum_{i=1}^{k} g_i \cdot E_i(x), \quad (g_1,\dots,g_k) = \text{TopK}(\text{Router}(x))$$

Router 就是一个 $E$ 类的线性分类器：

$$s = x W_g^\top\in\mathbb{R}^E,\quad W_g\in\mathbb{R}^{E\times d}$$

打分函数有两种：

- **softmax**（传统）：$p_i = e^{s_i}/\sum_j e^{s_j}$。所有专家分数和为 1。
- **sigmoid**（DeepSeek-V3 起，GLM/Kimi/DSV4 全用）：$p_i=\sigma(s_i)$。多标签语义，专家之间不竞争。

选完 top-k 后通常重新归一化：$g_i = p_i / \sum_{j=1}^k p_j$（`norm_topk_prob=True`），再乘一个 `routed_scaling_factor`（DSV4 是 1.5，GLM 是 2.5）补偿 top-k 选择带来的方差变化。

### 组级路由（grouped top-k）

$E=256$ 个专家直接全局 top-k 容易负载不均。DeepSeek-V3 引入：把专家分成 $n_g$ 组，先选 top-$k_g$ 个组，再在选中的组里选 top-k 专家。

GLM `modeling_glm_moe_dsa.py:488`（`GlmMoeDsaTopkRouter.forward`）：

```python
scores = router_logits.sigmoid()
scores_for_choice = scores + self.e_score_correction_bias
# 每组取 top2 求和作为组分
group_scores = scores_for_choice.view(-1, n_group, E//n_group).topk(2, dim=-1)[0].sum(-1)
group_idx = group_scores.topk(topk_group, dim=-1)[1]          # 选组
# mask 掉没选中的组，再全局 top-k
scores_for_choice = scores_for_choice.masked_fill(~group_mask, -inf)
topk_indices = scores_for_choice.topk(top_k, dim=-1)[1]
topk_weights = scores.gather(1, topk_indices)
topk_weights /= topk_weights.sum(-1, keepdim=True) + 1e-20   # 归一化
topk_weights *= routed_scaling_factor
```

### 共享专家

除了路由专家，还有 1–2 个**每个 token 都过**的共享专家（DSV4/GLM/Kimi 都有）。共享专家捕获通用知识，路由专家捕获专业化知识。

### 负载均衡

训练时如果不加约束，router 会倾向于把所有 token 发给少数几个专家（rich-get-richer）。两种解法：

- **辅助 loss**（传统 Switch Transformer）：加一项 $\text{load}\cdot\text{score}$ 的乘积损失，鼓励均匀分配。
- **noaux_tc bias**（DeepSeek-V3）：每个专家维护一个可学习偏置 $b_i$，被选太多就降它的分。**偏置只影响选择，不影响权重**。GLM 注册了 `e_score_correction_bias` 但当前 modeling 代码恒零；DSV4 在训练时动态更新。

### Shape（GLM $E=256, k=8, d=6144$, 专家 latent $d_f=2048$）`[配置值]`

```
x:              (B·S, 6144)
gate(x):        (B·S, 256)          sigmoid 打分
topk:           (B·S, 8) indices, (B·S, 8) weights
每个专家: gate_up_proj (2×2048, 6148? 实际 2*2048=4096 行)
         down_proj    (6144, 2048)
每专家参数: 3 × 6144 × 2048 ≈ 37.7M
256 专家:    9.66B/层（但每 token 只激活 8 个 ≈ 302M + 1 共享）`[推导]`
```

### 源码锚点

- GLM 专家循环（`modeling_glm_moe_dsa.py:514` `GlmMoeDsaExperts.forward`）：对每个命中的专家，用 `index_add_` 把结果累加回对应 token 位置。这是**参考实现**，生产用 grouped GEMM / fused MoE kernel。`[源码事实]`
- Kimi `modeling_kimi_linear.py:841` `moe_infer`：先按 expert id 排序 token（`argsort`），再逐专家批量算——比 GLM 的 for-loop 高效。`[源码事实]`
- DSV4 用 FP4 权重 + tilelang kernel（`inference/kernel.py`，536 行）。`[源码事实]`

### Latent MoE（Kimi 独有，06 章细讲）

Kimi 在路由前先把 $d=7168$ 投影到 latent $d_l=3584$，专家在 3584 维空间计算，输出再投回 7168。这让 896 个专家的总参数从 $896\times 3\times 7168\times 33792$ 暴减到 $896\times 3\times 3584\times 3072$——2.8T 总参而激活只有 104B 的关键。

### 去掉会怎样

- 用 dense FFN：参数量 = 激活参数量，没法做大。
- 不做负载均衡：训练崩，少数专家被挤爆。

## 10. MLA（Multi-head Latent Attention）

### 定义

DeepSeek-V2 提出的注意力。MHA/GQA 的 KV cache 是 $O(h_{kv}d_h)$ per token；MLA 把 K 和 V 联合压缩到一个低秩向量 $c_t^{KV}\in\mathbb{R}^{d_c}$，缓存只存 $c_t^{KV}$，推理时再上投影回多头。

### 数学

**压缩 KV**：

$$c_t^{KV} = W^{DKV} h_t \in\mathbb{R}^{d_c}$$

解压时：

$$k_t^{nope} = W^{UK} c_t^{KV} \in\mathbb{R}^{h d_k},\qquad v_t = W^{UV} c_t^{KV}\in\mathbb{R}^{h d_v}$$

**低秩 Q**（同理）：

$$c_t^Q = W^{DQ} h_t \in\mathbb{R}^{d_r},\qquad q_t = W^{UQ} c_t^Q\in\mathbb{R}^{h(d_k+d_r^{rope})}$$

这里关键洞察：注意力是 $\text{softmax}(Q K^\top/\sqrt{d}) V$。如果我们缓存的是压缩后的 $c^{KV}$ 而不是 $k,v$，那么：

$$o = \text{softmax}(Q (W^{UK} c^{KV})^\top) W^{UV} c^{KV} = \text{softmax}(Q c^{KV\top} W^{UK\top}) W^{UV} c^{KV}$$

矩阵乘法可结合，运行时只需把 $Q$ 吸收掉 $W^{UK\top}$ 即可，缓存压到 $d_c$ 维。

### RoPE 兼容性问题

RoPE 作用在 $k_t$ 上，而 $k_t = W^{UK}c_t^{KV}$ 是 $c_t^{KV}$ 的线性函数。如果只缓存 $c_t^{KV}$，解压后再做 RoPE，就无法利用"吸收矩阵乘法"的优化（因为 RoPE 在非线性的位置索引上）。

**解法（DeepSeek-V2 起）**：拆分出一小部分 $k_t$ 专门承受 RoPE：

$$k_t = [k_t^{nope};\; k_t^R],\quad k_t^R\in\mathbb{R}^{d_H^R}\ \text{（64 维）}$$

- $k_t^{nope}$（位置无关）和 $v_t$ 走低秩压缩路径，缓存 $c_t^{KV}\in\mathbb{R}^{d_c}$。
- $k_t^R$（带位置）单独缓存，只有 64 维，每头共享（MQA 式）。

所以实际每 token 缓存：$d_c + d_H^R = 512+64 = 576$ 个 bf16 = **1152 字节**，和头数 $h$ 完全无关。`[推导]`

### Shape（GLM $d=6144, d_c=512, d_r=2048, h=64, d_h=256$）`[配置值]`

```
h_t:                  (B, S, 6144)
─── Q 路径 ───
q_a_proj(h):          (B, S, 2048)         ← 低秩
q_a_layernorm
q_b_proj:             (B, S, 64×256=16384) ← 上投影到多头
split → q_pass(192) + q_rot(64) per head
─── KV 路径 ───
kv_a_proj_with_mqa(h):(B, S, 576) = [512; 64]
split:
  k_pass 压缩: (B,S,512) → kv_a_layernorm → kv_b_proj → (B,S,64×(192+256))
                → split → k_nope(32,192) + v(32,256)
  k_rot:      (B,S,64) → view (B,1,S,64) → expand 到 64 头（MQA 共享）
─── 拼接 ───
q = [q_pass(192); q_rot(64)]   (B,32,S,256)
k = [k_pass(192); k_rot(64)]   (B,32,S,256)
v =                            (B,32,S,256)
─── 缓存 ───
每层每 token 只存:  [c_KV(512); k_rot(64)] × 2 bytes = 1152 B
```

### 源码锚点

GLM `modeling_glm_moe_dsa.py:385`（`GlmMoeDsaAttention.forward`）：

```python

q_states = self.q_b_proj(q_resid).view(query_shape).transpose(1,2)
```

### DSV4 的变体：单 KV 头 + 分组 O 投影

DSV4 把 MLA 改得更激进（`inference/model.py:442` `Attention`）：

- `wkv: Linear(d, head_dim=512)` —— **K/V 合一个投影，单头**（不是多头压缩）。
- `wo_a`/`wo_b`：输出也低秩化，分成 `o_groups=8` 组，每组投到 `o_lora_rank=1024` 再聚合。
- 注意力分数对 Q 做 RMS 归一化（`q *= rsqrt(mean(q²)+eps)`），稳定训练。

这是 DSV4 独有的"极致压缩"变体，07 章细讲。

### 去掉会怎样

换回 GQA：KV cache 从头数无关的 $d_c=512$ 涨回 $h_{kv}d_h$。以 GLM 为例，若用 8 KV 头×256，缓存涨 4.5 倍，1M 上下文从 180MB 涨到 800MB/层——78 层就是 62GB，单卡放不下。

## 11. MTP（Multi-Token Prediction）与推测解码

### 概念

标准自回归一次预测一个 token。MTP 让模型一次预测后 $m$ 个 token（通常 $m=1$），训练时增加一个辅助头预测第 $t+1$ 个 token，推理时用作"草稿"做推测解码。

### 为什么训练时也要 MTP

- 多 token 目标迫使模型学习更长程的依赖（官方报告称能提升下游评估；独立消融在开源参考代码中无法验证，因为训练代码未发布）。`[官方材料]`
- 推理时草稿 + 主模型验证：草稿对了就一次接受多个 token，错了回退。接受率决定加速比（通常 1.5–2×）。

### 重要区分：权重在 ≠ 在用

六个模型里 MTP 的接线状态各不相同，这是"架构 vs 实现"混淆的重灾区：

| 模型 | config 声明 | 权重存在吗 | transformers 建模用吗 | 推理引擎 |
|---|---|---|---|---|
| GLM | `num_nextn_predict_layers=1` | ✅ 藏在 `model.layers.78` | ❌ 加载时忽略 | 引擎实现（vLLM/SGLang） |
| Kimi | 报告说 1 层 / cfg `num_nextn_predict_layers=0` | ⚠️ 不一致 | ❌ | 未在参考代码体现 |
| DSV4 | `num_nextn_predict_layers=1` | ✅ `mtp.0/1/2` 完整 | ❌ 主模型不调 | `generate.py` **未调用 forward_spec**（未接线） |
| Qwen3.6 | `mtp_num_hidden_layers=1` | ✅ `^mtp.*` 键 | ❌ `_keys_to_ignore` | vLLM `qwen3_next_mtp` / SGLang NEXTN |

**源码事实**：所有四个官方模型的开源参考建模代码都不在主 forward 里跑 MTP。MTP 的实际执行依赖 vLLM/SGLang 等引擎的特定实现。

### DSV4 的 DSpark（07 章细讲）

DSV4 把 MTP 做成了完整的"草稿模型"：3 个 DSparkBlock + MarkovHead（token→256 隐状态→token 转移矩阵）+ ConfidenceHead（决定接不接受草稿）。代码在 `inference/model.py` 里完整，但 `generate.py` 没有调用 `forward_spec`——属于"代码已写好但没接生产循环"的状态。

## 12. 量化基础（FP8 / FP4）

### 为什么需要

大模型权重是最大的显存/内存带宽开销。bf16 每参数 2 字节；FP8 1 字节；FP4 半字节。推理是 memory-bound（算力在等权重从 HBM 搬到 SRAM），所以量化直接加速。

### FP8（E4M3）

- 1 个符号位 + 4 个指数位 + 3 个尾数位。
- 动态范围 ±448，精度 ~8 bit。
- 现代 GPU（H100）原生支持 FP8 GEMM。
- DSV4 非专家权重用 FP8：`quantization_config.fmt="e4m3", weight_block_size=[128,128]`，每个 128×128 块有一个 `ue8m0` 标度（8 位无标度指数浮点）。

### FP4（E2M1）

- 1 符号 + 2 指数 + 1 尾数。只有 16 个可表示值：`{0, ±0.5, ±1, ±1.5, ±2, ±3, ±4, ±6}`。
- DSV4 的 256 个路由专家用 FP4 存（`expert_dtype="fp4"`）。每参数 0.5 字节，256 个专家从 bf16 的 ~38GB 压到 ~10GB。
- 计算时反量化成 FP8/bf16（`convert.py` 做 FP4→FP8 的标度折叠）。

### 为什么只有专家量化

专家层是 MoE 模型里最大的权重块（DSV4 256 专家占总参数 90%+），但每 token 只激活 6 个。量化专家：
- 省显存（最大收益）。
- 精度损失可控（路由专家本来就是"弱专家分工"，对单专家精度要求不高）。
- 非专家（attention、共享专家、router）保持 bf16/FP8，保护精度。

### microscaling（MX）格式

DSV4 用的 `float4_e2m1fn_x2` 是 NVFP4（Microscaling FP4）：每 16 个元素共享一个 `e8m0` block scale。块内值 = `scale × fp4_value`。这比"每元素一个 scale"省大量元数据，又比"每张量一个 scale"精度高。

### 源码锚点

`dsv4/inference/kernel.py`（536 行 tilelang）定义了 `act_quant`、`fp4_act_quant`、`fp4_gemm` 等 kernel。`convert.py` 处理 FP4→FP8 的权重转换。

### 重要：量化不改变架构

DavidAU 的 GGUF（Q4_K_M、IQ2_M 等）是**权重量化格式**，不改变模型的计算图或行为。一个 FP4 量化的 DSV4 和 bf16 的 DSV4 是同一个模型，只是精度不同。把量化层级的变化当成"新架构"是常见的分析错误。
